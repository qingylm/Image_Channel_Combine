# Image_Channel_Combine

Create a PNG image by mapping a grayscale image to the RGBA channels

一个基于 **Python + Gradio + Pillow** 的本地网页图片通道工具：把若干张灰度图 / 蒙版装进 **R / G / B / A** 四个通道，
合成为一张 **RGBA PNG**；也能反过来把一张图片**拆分成四个通道**。

 R ────►│              │                      │              │────► R.png
 G ────►│  RGBA 打包    │────► RGBA PNG        │  通道拆分     │────► G.png
 B ────►│  (拼接)       │      (任意尺寸 /     │              │────► B.png
 A ────►│              │       等大 1:1)      │              │────► A.png
        └──────────────┘                      └──────────────┘

## 1. 功能一览

| 功能 | 说明 |
| --- | --- |
| 三个工作面板 | ① 通道合成（自定义尺寸）② 四宫格拼图（四张 → 一张 2×2）③ 通道拆分（一张 → R/G/B/A） |
| 四通道上传 | R / G / B / A，支持拖拽、点击选择、粘贴剪贴板图片 |
| **空通道按 0 填充** | 任一通道没上传图片时，该通道整幅按 **0** 填充（R/G/B = 黑，A = 完全透明），不阻断合成；可以只上传其中几个通道 |
| 输出尺寸 | 宽 / 高任意设置（1 – 16384），内置常用尺寸预设；**四宫格拼图面板默认自动取第一张图的原始尺寸（每块减半）** |
| 三种缩放模式 | `Stretch` 拉伸 / `Fit` 保持比例 + 黑边填充 / `Crop` 保持比例 + 居中裁剪 |
| **16 / 32-bit 贴图支持** | 16-bit 灰度、32-bit 整数、浮点输入按位深正确换算成 8-bit，**不会被截断成纯白**（见第 9 节） |
| 通道反转 | Alpha 反转（0↔255）、RGB 反转 |
| 实时预览 | 修改任一参数即时刷新四个通道预览与最终 RGBA 预览 |
| 1:1 细节预览 | 额外显示输出图中心 256×256 的**原始像素**裁剪块，高频贴图缩放后看不出细节时用它确认 |
| 透明棋盘格 | Alpha / RGBA 预览以棋盘格表示透明区域（只画在图像本身，留白不算透明） |
| **通道拆分导出** | 一张图拆成四个**单通道灰度 PNG**，可分别下载或一次性下载 ZIP |
| **通道池（拆分 → 合成直连）** | ③ 拆出的通道自动进入 ① 的「通道池」，下拉选择即可接进 R/G/B/A 槽位；也可一键「送入通道合成」，**不用下载再重传**。列表默认只保留**最新一次拆分**，历史条目可一键清理 |
| PNG 压缩等级 | 0（最快）– 9（最小），均无损 |
| 下载与归档 | 生成后可下载，并自动归档到 `output/` 目录（可关闭） |
| 命令行模式 | `cli.py` 支持四宫格拼图与通道拆分，便于批量 / 脚本调用 |

## 2. 三个工作面板

启动后网页顶部是三标签页，互不影响：

```text
┌─────────────────────────────────────────────────────────────────────┐
│  RGBA Image Composer                          v1.2.0 · Gradio       │
├─────────────────────────────────────────────────────────────────────┤
│ [① 通道合成] [② 四宫格拼图] [③ 通道拆分]                             │
├──────────────────────────────┬──────────────────────────────────────┤
│  R / G / B / A 上传            │  四个通道预览                        │
│  Alpha 来源 / 尺寸 / 缩放模式   │  RGBA 输出预览（棋盘格）              │
│  位深换算 / 压缩等级 / 归档     │  1:1 细节预览（中心 256×256）         │
│  [生成 PNG] [清空]             │                                      │
└──────────────────────────────┴──────────────────────────────────────┘
```

### 2.1 ① 通道合成 · 四通道 → 自定义尺寸

通用面板：四张图分别缩放后合成，输出尺寸、缩放模式、Alpha 来源全部可调。适合需要精确控制尺寸的场合。

面板里的「**通道池**」用来直接复用 ③ 拆出来的通道（见 2.4）：下拉里列出 `output/` 目录下的图片，
`[通道]` 标记的就是拆分导出的单通道灰度图；选中某一项即把它接进对应的 R/G/B/A 槽位，
选「（不使用）」清空该槽位。另有「自动匹配最新一套 `_R/_G/_B/_A`」一键填满四个槽位。

### 2.2 ② 四宫格拼图 · 四张 → 一张 2×2

把四张图**各自保留自己的 RGBA 通道**（颜色与透明度都不拆），分别放进新图的
**左上 / 右上 / 左下 / 右下**四个位置，合成一张新图：

```text
四张 2048×2048 ──(每张缩放到 1024×1024)──► 一张新的 2048×2048
        ┌───────────────┬───────────────┐
        │   ① 左上 TL    │   ② 右上 TR    │   每块 = 输出尺寸的一半
        ├───────────────┼───────────────┤
        │   ③ 左下 BL    │   ④ 右下 BR    │
        └───────────────┴───────────────┘
```

* 输出尺寸默认 **自动 = 第一张图的原始尺寸**，于是四张 2048×2048 → 输出 2048×2048、每块 1024×1024
  （也可以「手动指定」宽高，例如 4096×4096 → 每块 2048×2048，即原尺寸 1:1 放入）
* 每块适配方式：`拉伸铺满` / `保持比例 + 透明填充` / `保持比例居中裁剪`；源图与格子比例相同时三者结果一致
* 空格子（没上传的位置）保持**透明**；`fit` 模式的留白同样是透明
* 拼完给出报告：

  ```text
  左上: 2048×2048 I;16 → 1024×1024（stretch · 缩放到 1024×1024）
  右上: 2048×2048 I;16 → 1024×1024（stretch · 缩放到 1024×1024）
  左下: 2048×2048 I;16 → 1024×1024（stretch · 缩放到 1024×1024）
  右下: 2048×2048 I;16 → 1024×1024（stretch · 缩放到 1024×1024）
  输出: 2048×2048 · 每块 1024×1024（各自保留 RGBA）
  ```

### 2.3 ③ 通道拆分 · 一张 → R/G/B/A

上传一张图片，拆出它的四个通道：

* 四个通道分别预览、分别下载，另附一个 ZIP（`<图片名>_RGBA_channels.zip`）
* 导出的是**单通道灰度 PNG**（不是伪 RGBA），体积更小，导入 Unity / Substance / Photoshop 当遮罩时语义正确
* 原图**没有 Alpha** 时，A 输出 255（完全不透明），状态栏会写明「无（按 255 不透明合成）」
* 灰度图（`L`）：R = G = B = 该灰度值；16-bit 灰度会先按位深换算成 8-bit 再拆分
* 通道**固定导出到** `output/<图片名>_split/`（ZIP 可选），这样 ① 的通道池随时能读到
* 「**→ 送入 ① 通道合成**」按钮：把刚拆出的四个通道按 R/G/B/A 直接接好，并立刻刷新 ① 的实时预览

### 2.4 拆分 → 合成的完整流程（不用下载再上传）

```text
③ 通道拆分                     ① 通道合成
┌──────────────┐            ┌────────────────────────────┐
│ 一张 tex.png  │  拆分      │ 通道池（来自 output/）       │
│      ↓        │ ────────►  │  → R 槽位 [tex_split/…_R.png]│
│ tex_R.png     │  写入      │  → G 槽位 [tex_split/…_G.png]│
│ tex_G.png     │  output/   │  → B 槽位 [tex_split/…_B.png]│
│ tex_B.png     │  tex_split/│  → A 槽位 [tex_split/…_A.png]│
│ tex_A.png     │            │            ↓  实时预览 / 生成 PNG│
└──────────────┘            └────────────────────────────┘
        └── 也可以点「→ 送入 ① 通道合成」一步接好四个槽位
```

两种接法：

1. **自动**：③ 里点「→ 送入 ① 通道合成」→ 四个槽位按顺序填好（R→R、G→G、B→B、A→A）
2. **手选**：在 ① 的通道池里逐个下拉选择，可以把任意通道放到任意槽位（例如把某张图的 G 通道接到 B 槽位）；
   或点「自动匹配最新一套 _R/_G/_B/_A」一键匹配

**列表范围与历史清理**（通道池只保留最新那一套，不会被历史条目淹没）：

| 按钮 / 选项 | 行为 |
| --- | --- |
| 列表范围 = **只列最新一次拆分的通道**（默认） | 下拉里只有**最新那个 `<名字>_split/` 的四个通道**（按 R/G/B/A 排序），历史拆分不再出现 |
| 列表范围 = 列出 `output/` 里全部图片 | 列出 `output/` 下全部图片（含历史拆分与打包 / 拼图结果），按修改时间倒序，最多 200 项 |
| **刷新列表** | 按当前「列表范围」重新扫描（默认下等于"清掉历史条目、只留最新那套"），状态栏显示项数与最新拆分目录名 |
| **清理历史拆分文件夹** | 把 `output/*_split/` 里除最新一个之外的历史拆分目录**从磁盘删除**（保留最新那套），并报告删除数量与释放空间 |

每次在 ③ 完成拆分后，通道池也会自动按当前范围刷新，所以刚拆出来的四个通道一定在列表最上方。
切换「列表范围」会立即刷新，不需要额外点按钮。

> 磁盘删除只发生在你点「清理历史拆分文件夹」时；「刷新列表」本身不动任何文件。

## 6. 使用流程

### 6.1 通道合成

1. 准备通道图（PNG / JPG / TIFF / BMP / WEBP…，可 8-bit 或 16-bit）
2. 依次拖入 `R / G / B / A` 四个输入框 —— **可以只上传其中任意几个**，未上传的按 0 处理
3. 选择 Alpha 来源：`上传 Alpha 图片` 或 `使用常量 Alpha`（255 = 完全不透明）
4. 设置输出宽高（或选尺寸预设），选择缩放模式
5. 右侧实时预览四个通道 + 最终 RGBA，用「1:1 细节预览」确认细节
6. 点击「生成 PNG」→ 下载，并（默认）归档到 `output/`

### 6.2 四宫格拼图

1. 按位置把四张图拖入 `① 左上 TL / ② 右上 TR / ③ 左下 BL / ④ 右下 BR`（可以只放其中几张，空格子保持透明）
2. 输出尺寸保持「自动（= 第一张图的原始尺寸，每块减半）」
3. 右侧预览确认四块内容与位置
4. 点「一键拼接 PNG」→ 下载 2×2 拼图

### 6.3 通道拆分

1. 拖入一张要拆分的图片
2. 看四个通道预览（R / G / B / A）
3. 点「拆分并导出通道」→ 四个灰度 PNG + 一个 ZIP，并写入 `output/<图片名>_split/`
4. 想让它们直接参与合成：点「→ 送入 ① 通道合成」，或回到 ① 用「通道池」逐个选择

## 7. 三种缩放模式

以输入 `1024 × 512`、输出 `1024 × 1024` 为例：

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `Stretch` 拉伸 | 强制拉伸到 1024×1024，比例会变形 | 通道图本来就与目标尺寸一致、或允许变形的高度图 |
| `Fit` 填充 | 保持比例缩小到 1024×512，上下用黑色（Alpha=0）补齐 | 不想变形、允许出现透明 / 黑边 |
| `Crop` 裁剪 | 保持比例放大到 2048×1024，居中裁出 1024×1024 | 纹理、贴图，要求铺满且不变形 |

四个通道使用**同一种**缩放模式，保证像素对齐。四宫格拼图面板里这三种模式对应「每块适配方式」：
源图与格子比例一致时（例如 2048² → 1024²）三种结果完全相同。

## 8. 空通道 = 0（未上传的通道）

**任何一个通道没有上传图片时，该通道整幅按 `0` 填充**，不会报错、也不会阻断合成：

| 空通道 | 填入值 | 结果 |
| --- | --- | --- |
| R 为空 | 0 | 红色分量为 0（偏青 / 暗） |
| G 为空 | 0 | 绿色分量为 0（偏洋红 / 暗） |
| B 为空 | 0 | 蓝色分量为 0（偏黄 / 暗） |
| A 为空 | 0 | **完全透明**（PNG 里 alpha = 0） |

* 可以只上传 1–4 个通道，例如「只给 R 和 G」→ `B = 0`、`A = 0`（全透明）
* 四个通道全空时输出一张 `宽 × 高` 的全 0 图：RGBA = `(0, 0, 0, 0)`
* 想让空 Alpha 变成「完全不透明」，把 Alpha 来源切到 **使用常量 Alpha** 并设为 `255`
* 空通道填充发生在**反转之前**：勾选「Alpha 反转」时 `0 → 255`；勾选「RGB 反转」时空的 R/G/B `0 → 255`
* 状态栏会明确写出哪些通道被按 0 填充
* 只有「**给了路径但读不出来**」（文件不存在、格式不支持、损坏）才会报错 —— 空 ≠ 坏

填充值可通过 API 调整（默认 0）：

```python
from image_processor import process_channels

filled = []
_, _, _, _, rgba = process_channels(
    r_path="R.png", g_path=None, b_path=None, a_path=None,   # 只给 R
    width=1024, height=1024,
    missing_value=0,          # 空通道填充值
    filled_channels=filled,   # 回传被填充的通道名，用于提示
)
print(filled)   # ['G', 'B', 'A']
```

## 9. 高位深（16-bit / 32-bit / 浮点）输入

**这是最容易踩的坑**：Pillow 的 `im.convert("L")` 对 `I;16` / `I` / `F` 模式是**裁剪**语义 ——
大于 255 的值一律变成 255。一张 16-bit 灰度贴图（例如值域 38475–64033）会被整张压成 **纯白**，
于是「只填 G 通道」就得到一张纯绿色图，看起来像工具坏了，其实是数据在转 8-bit 时被丢掉了。

本工具的正确处理：

| 输入模式 | 含义 | scale（默认） | normalize |
| --- | --- | --- | --- |
| `I;16` / `I;16B/L/N` | 16-bit 整数（PNG / TIF） | ÷257（`v >> 8`），保留绝对数值 | 按实际 min–max 拉伸到 0–255 |
| `I` | 32-bit 整数（部分 TIFF） | 按最大值线性缩放 | 同上 |
| `F` | 32-bit 浮点 | 0.0–1.0 视为满量程 ×255 | 同上 |
| `L` / `RGB` / `RGBA` / `P` … | 8-bit | 亮度转灰度，行为不变 | 同左 |

界面上是「**16 / 32-bit 位深换算**」下拉框：

* **满量程换算（默认）**：`38475 → 150`、`65535 → 255`，数值比例与源一致，适合粗糙度 / AO / 高度图这类要保留绝对值的贴图
* **实际范围拉伸**：把该图自己的 min–max 拉满 0–255，适合只用了部分量程的蒙版（例如值域 10000–20000）

自检方式：状态栏的「源位深」会写出来，例如

```text
源位深： G: I;16->L(scale) · A: I;16->L(scale)
```

看到 `I;16` 说明原始位深被正确读取；若显示 `RGB->L`，说明文件在进入处理前已经被转成 8-bit 了。

> 实现要点：Gradio 的 `gr.Image` **默认 `image_mode="RGB"`**，会在服务端先做一次 `convert("RGB")`，
> 同样会把 16-bit 截断成纯白。所以本项目的输入组件显式设为 `image_mode=None`，
> 让原始文件路径直接进入 `image_processor.to_grayscale_8bit()` 处理。

## 10. 命令行模式（批量 / 脚本）

```bash
# 等大拼接（通道打包，CLI 的默认模式）：四张 2048x2048 -> 一张 2048x2048 RGBA，尺寸自动取自输入
python cli.py --r R.png --g G.png --b B.png --a A.png

# 只给 R/G：B 按 0（黑）填充、A 按 0（完全透明）填充
python cli.py --r R.png --g G.png

# 手动指定尺寸与文件名，Alpha 使用常量 255（完全不透明）
python cli.py --r R.png --g G.png --b B.png --size 1024x1024 --alpha-const 255 -o out/tex.png

# 四宫格拼图：四张 2048x2048 -> 一张 2048x2048（每块 1024x1024，各自保留 RGBA）
python cli.py --mosaic --tl a.png --tr b.png --bl c.png --br d.png

# 通道拆分：一张图 -> R/G/B/A 四个灰度 PNG + ZIP
python cli.py --split tex.png --outdir channels/

# 保持比例裁剪 + Alpha 反转 + 压缩等级 9
python cli.py --r R.png --g G.png --b B.png --a A.png --size 2048x2048 --mode crop --invert-alpha --compress 9
```

| 参数 | 说明 |
| --- | --- |
| `--r / --g / --b` | 三个颜色通道图片，**可省略**，省略的通道按 0（黑）填充 |
| `--a` | Alpha 通道图片，**可省略**（按 0 = 完全透明填充）；与 `--alpha-const` 二选一 |
| `--alpha-const 0-255` | 使用常量 Alpha，例如 255 = 完全不透明 |
| `--size WxH` | 输出尺寸；通道合成模式下省略则自动取第一张通道图的原始尺寸；拼图模式下省略 = 第一张图的尺寸（每块减半） |
| `--mode` | `stretch` / `fit` / `crop`，默认 `stretch`（通道合成：尺寸不一致时如何对齐；拼图：每块如何适配格子） |
| `--invert-alpha` / `--invert-rgb` | 通道反转 |
| `--depth scale\|normalize` | 16/32-bit 位深换算，默认 `scale`（满量程 ÷257） |
| `--compress 0-9` | PNG 压缩等级，默认 6 |
| `-o / --output` | 输出路径，省略则写入 `output/` |
| `--split IMAGE` | 拆分模式：把该图片拆成 R/G/B/A 四个通道（忽略 `--r/--g/--b/--a`） |
| `--outdir DIR` | 拆分模式的输出目录，省略则写入 `output/<图片名>_split/` |
| `--mosaic` | 四宫格拼图模式：把 `--tl/--tr/--bl/--br` 四张图拼成一张 2×2 新图 |
| `--tl / --tr / --bl / --br` | 拼图模式的左上 / 右上 / 左下 / 右下图片；可只给其中几张，空格子保持透明 |

## 11. Python API

`image_processor.py` 可直接当库用（公开函数全部使用关键字参数，避免参数错位）：

```python
from image_processor import (
    process_channels,      # 四通道 -> RGBA（可指定尺寸、缩放模式）
    pack_same_size,        # 四张同尺寸 -> 一张同尺寸（通道打包，自动尺寸、1:1）
    mosaic_quadrants,      # 四张图各自保留 RGBA -> 一张 2×2 新图（左上/右上/左下/右下）
    split_channels,        # 一张 -> R/G/B/A 四个 8-bit 通道
    combine_to_png,        # 一步写盘
    save_png,              # 保存 RGBA PNG
    save_channel_png,      # 保存单通道灰度 PNG
    zip_files,             # 打包成 ZIP
    probe_image_info,      # 只读文件头：尺寸 / 模式 / 是否自带 Alpha / 位深
    list_output_images,    # 列出 output/ 下可复用的图片（通道池用）
)

# 1) 四通道合成（自定义尺寸）
r, g, b, a, rgba = process_channels(
    r_path="R.png", g_path="G.png", b_path="B.png", a_path="A.png",
    width=1024, height=1024,
    resize_mode="crop",       # stretch | fit | crop
    invert_alpha=False, invert_rgb=False,
    high_bitdepth="scale",    # scale | normalize
)
save_png(rgba, "out/tex.png", compress_level=6)

# 2) 等大拼接 / 通道打包：四张 2048² -> 一张 2048²
report = []
*_, rgba, size = pack_same_size(
    r_path="rough.png", g_path="ao.png", b_path="mask.png", a_path="alpha.png",
    width=None, height=None,            # None = 自动取第一张图的原始尺寸
    mismatch_mode="stretch", high_bitdepth="scale",
    size_report=report,
)
print(size, report)

# 3) 四宫格拼图：四张 2048² 各自保留 RGBA -> 一张 2048²（每块 1024²）
report = []
atlas, size = mosaic_quadrants(
    tl_path="tl.png", tr_path="tr.png", bl_path="bl.png", br_path="br.png",
    width=None, height=None,            # None = 自动 = 第一张图的尺寸（每块减半）
    tile_mode="stretch",                # 每块适配：stretch | fit（透明填充）| crop
    high_bitdepth="scale",
    size_report=report,
)
save_png(atlas, "out/mosaic.png")

# 4) 通道拆分
r, g, b, a, info = split_channels("tex.png", high_bitdepth="scale")
for label, channel in zip("RGBA", (r, g, b, a)):
    save_channel_png(channel, f"out/tex_{label}.png")
print(info["mode"], info["size"], info["has_alpha"], info["alpha_source"])
```

核心只有一行合并逻辑：

```python
rgba = Image.merge("RGBA", (r, g, b, a))   # 四张 "L" 灰度图 -> RGBA
rgba.save("out.png", format="PNG")         # PNG 无损保留 Alpha
```

## 12. 通道与 Alpha 说明

RGBA 每个像素由 4 个 8-bit 通道组成，取值范围 `0 – 255`：

| 通道 | 名称 | 作用 |
| --- | --- | --- |
| R | Red | 红色分量 |
| G | Green | 绿色分量 |
| B | Blue | 蓝色分量 |
| A | Alpha | 透明度（灰度遮罩） |

| Alpha 值 | 含义 |
| ---: | --- |
| 0 | 完全透明 |
| 64 | 约 25% 不透明 |
| 128 | 约 50% 不透明 |
| 192 | 约 75% 不透明 |
| 255 | 完全不透明 |

即：**黑 = 透明，白 = 不透明**。若遮罩语义相反，勾选「Alpha 反转」（等价于 `255 - x`），原始文件不会被修改。

## 13. 常见问题（FAQ）

**Q：四张图尺寸不一致会怎样？**
A：通道合成面板各自缩放到你设定的输出尺寸后再合并，最终严格像素对齐；
四宫格拼图面板按「每块适配方式」把每张图塞进自己的格子（`拉伸 / 保持比例+透明填充 / 保持比例裁剪`），
并给出每块的源尺寸 → 格子尺寸报告。

**Q：四张 2048×2048 拼图后，为什么每块只剩 1024×1024？**
A：因为 2×2 拼图的每块 = 输出尺寸的一半。默认「自动」= 第一张图的原始尺寸（2048），
所以每块 1024。想要每块保持原始 2048 分辨率，把输出尺寸手动设为 **4096×4096** 即可。

**Q：拼图时 16-bit 贴图会变白吗？**
A：不会。拼图与拆分共用同一套位深处理（`I;16 → ÷257`，可切换「实际范围拉伸」），
16-bit 灰度贴图会正确换算成 8-bit 后再放进格子。

**Q：只填了 G 通道，输出却是「纯绿色」，一点细节都没有？**
A：两个常见原因，都能在界面上确认：

1. **输入是 16-bit 贴图**（`I;16`）。旧行为下 `convert("L")` 把 >255 的值全截断成 255 → G 全白 → `(0,255,0)` 纯绿。
   现已修复：状态栏「源位深」应显示 `I;16->L(scale)`；想要满对比可把位深换算切成「实际范围拉伸」。见第 9 节。
2. **贴图本身是高频噪点、且输出尺寸很大**。整图预览会被缩到几百像素，噪点被平均掉后看起来就是纯色 —— 这是显示问题，
   不是数据问题。用「1:1 细节预览（中心 256×256）」看原始像素即可确认，或直接下载 PNG 再用 Photoshop 看。

**Q：为什么输出的图整体发暗 / 偏色？**
A：检查是不是有颜色通道留空了 —— 空通道是 0，会让整体偏暗或偏色。状态栏的「空通道按 0 填充：…」可直接确认。

**Q：输出的 PNG 打开是黑的 / 完全透明？**
A：多半是 Alpha 通道放反了。用「Alpha 反转」或检查常量 Alpha 是否为 255。RGBA 预览带棋盘格，可直接看出透明区域。

**Q：只想把 RGB 合成为不透明 PNG？**
A：Alpha 来源选「使用常量 Alpha」，滑杆设为 255，不需要第 4 张图。

**Q：拆分出来的通道为什么是灰度图，不是彩色？**
A：通道本身就是单通道数据。导出为 `L` 模式灰度 PNG 体积更小，导入 Unity / Substance / Photoshop 当遮罩时语义正确。
需要彩色预览的话，把灰度图分别放到对应颜色通道即可。

**Q：原图没有 Alpha，拆分出的 A 是什么？**
A：255（完全不透明），状态栏标注「无（按 255 不透明合成）」。

**Q：拆分出的通道，怎么直接用在 ① 通道合成里？**
A：两种方式（见 2.4）：③ 里点「→ 送入 ① 通道合成」一步接好四个槽位；
或在 ① 的「通道池」里逐个下拉选择，把任意通道放到任意槽位。通道池读的是 `output/` 目录，
所以拆完的通道在下次打开工具时依然可选，不需要下载再重新上传。

**Q：通道池里看不到我刚拆的通道？**
A：点「刷新列表」（每次拆分后也会自动刷新）。默认「列表范围」是**只列最新一次拆分的通道**，
所以只会看到最新那个 `<名字>_split/` 的四个文件；想看全部历史条目，把范围切到「列出 output/ 里全部图片」。

**Q：通道池里以前拆的图片堆了一大堆，怎么清掉？**
A：默认范围下历史条目本来就不会进列表；想把它们从磁盘也删掉，点「清理历史拆分文件夹」——
它会删除 `output/*_split/` 中除最新一个之外的所有历史拆分目录（只在你点击时执行，并报告删除了几个、释放多少空间）。
「刷新列表」本身不会删任何文件。

**Q：大尺寸（4096²、8192²）会不会很慢？**
A：4096×4096 通常 1 秒内完成；8192² 及以上内存占用明显上升（单张 RGBA 约 256 MB），建议 16384 以内。

**Q：端口被占用？**
A：`python app.py --port 8000`，或 `run.bat 8000`。

**Q：Gradio 版本太旧？**
A：本项目针对 Gradio 5 编写（`pip install -U "gradio>=5.0,<6.0"`）。若系统里同时存在全局的 Gradio 3，
请确认用的是虚拟环境里的解释器：`.\.venv\Scripts\python.exe app.py`。

**Q：`pip install` 卡住不动、CPU 占用高但没有下载？**
A：这是 pip 本地 HTTP 缓存的索引问题（缓存过大时解析会极慢），加 `--no-cache-dir` 即可：

```bash
pip install --no-cache-dir --progress-bar off -i https://pypi.tuna.tsinghua.edu.cn/simple "gradio>=5.0,<6.0" "Pillow>=10.0"
```
